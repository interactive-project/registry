# Plugin conformance checklist v1

Registry validates manifests and captures trusted live ports; registration alone is not evidence that an engine behaves correctly. A host/domain release should run the following checks for each advertised engine type and exact activity-schema version using the declared Protocol versions.

1. **Lifecycle:** create a session from a valid ActivitySpec; dispatch a valid action and an invalid identity/action; evaluate before and after state changes; dispose twice; verify disposal is idempotent and no later action changes state. Validate each DispatchResult and Result against Protocol v1 with the expected activity/session/attempt identity.
2. **Events:** attach the host's Events v1 adapter before creation. Validate each emitted ActivityEvent with the Events validator and local bus. Compare the ordered committed-transition trace with expected lifecycle/domain events, revisions, action causation and stable occurrence IDs. Rejected actions must not emit committed-state events. Do not put raw answers, source, credentials or native objects into events.
3. **Results:** exercise completed, pending/unevaluable and failure cases supported by the engine. Validate statuses, normalized score bounds, identity/revision, and evidence references. Native exceptions must become safe public failures rather than leaking stacks or secrets.
4. **Snapshots:** required only when `resumable` is advertised. Serialize to bounded JSON, validate Protocol Snapshot v1, restore into a fresh session with the same activity content digest and compatible engine/driver state versions, then continue the same trace. Compare state and result; ensure restore does not replay already committed events. Engines not advertising resumability must not be treated as snapshot-compatible.
5. **Isolation:** repeat without renderer registrations or browser/framework globals. Lazy-load the engine, run the same trace, and verify catalog contents/cache identity change only after registration completes. Unregistering removes future catalog entries but does not invalidate already-owned sessions.

`scripts/check-plugin-conformance.mjs` runs lifecycle, event, result and snapshot checks against a deliberately small fixture engine and the shared Protocol and Events validators/bus. `scripts/check-catalog.mjs` covers lazy-loader registration, registration removal, capability filtering and cache identity. Together these tests prove the checklist seam, not production quiz conformance, framework compatibility, a sandbox, or a universal persistence guarantee. Domain maintainers own real golden traces, schemas, required capabilities, driver versions and host/browser gates.
